## 1. 目标与范围

通过真实 RTC SDK，从指定位置的两个独立探测端验证加入频道和媒体接收，提供路径、阶段证据、状态、新鲜度和变化通知。不能用容器运行或 TCP 可达代替业务成功。

纳入：目标部署配置、独立测试身份、双端探测、周期调度、手动测试、分阶段结果、页面、历史、通知与离线交付。

不纳入：RTM 消息流程、媒体质量评分/MOS、真实用户录音录像、自动重启、完整告警中心、主备、多中心和多租户。

## 2. 路径与单轮流程

发送端 A（区域/位置） → RTC 私有化目标部署（集群） → 接收端 B（区域/位置）。

准备身份与频道 → 两端初始化 → 加入 → 发布合成媒体 → 订阅并接收媒体帧 → 校验本轮证据 → 离开与清理。

同机双端标明“同机探测”，不能宣称覆盖外部客户网络。结果绑定产品、目标、集群和路径，不默认归因到单个业务容器。探针独立于 Docker Agent，不要求每台业务机部署 SDK。

## 3. 专项功能与成功证据

### FR-03 RTC 产品线：媒体探测

单轮至少包括：准备测试身份/频道、两端初始化、加入、发布、订阅/接收、业务证据校验、离开和资源清理。

建议首个模板验证合成音频收发；视频模板仅在所选平台 SDK 支持并通过验证后启用。界面明确“已验证音频/视频”，不能用音频成功代替视频成功。

成功条件：

1. 两端加入同一专用测试会话。
2. 发布端实际提交合成媒体，不能仅记录发布调用成功。
3. 接收端识别预期发布者，在规定窗口内收到有效媒体帧，并记录首帧和接收数量/持续时间。
4. 接收证据属于本轮执行，不能复用上一轮或其他频道的回调。

发布成功但未收到媒体，判为接收阶段失败。只加入频道成功不算媒体链路成功。质量阈值（如丢包、卡顿、MOS）本期不默认纳入成功判据。

## 4. 探针、配置、调度与状态

### FR-01 探针登记与状态

- Agora 人员登记探针名称、唯一标识、网络区域和部署位置，配置独立机器凭证。
- 探针上报在线状态、最近心跳、版本、平台、SDK 版本及 RTC 支持能力。
- 失联或能力不满足时暂停向该探针分配新任务，关联任务标记未知。
- 停用探针后保留历史记录，任务配置明确显示不可执行原因。
- 探针凭证不能替代 Docker Agent 凭证或重启 Key。

### FR-02 目标部署与业务凭证

- 支持配置目标名称、产品、集群绑定、SDK 所需接入参数和独立测试凭证。
- 创建/修改敏感配置仅 Agora 人员可操作；查询不回显秘密，保存后支持替换。
- 使用专用测试频道、用户和账号，不接入真实用户会话，不采集真实用户音视频或消息。
- 支持现场所需的短期 Token 获取方式；具体签发方案由 SDK/鉴权模式评审确定，不把 App Secret 放入页面或截图。
- 配置连接检查与完整业务探测分别显示；仅鉴权或端口成功不得标为业务成功。

### FR-05 公共能力：任务配置、调度与手动测试

- Agora 人员可创建、编辑、启停和手动测试任务；客户运维查看结果。
- 配置包括产品线、目标部署、业务模板、两端探针、周期、单轮超时、防抖参数和描述。
- 同一任务只允许一轮执行中；重复点击手动测试复用或明确拒绝，不产生并发重复会话。
- 调度不追赶停机期间积压轮次。中心恢复后等待新任务，不把重启前缓存当作新成功。
- 配置变更产生新版本；旧版本迟到结果不覆盖新版本当前状态。
- 停用任务停止新调度并清理执行资源；界面显示“已停用”，不发送虚假恢复通知。

建议默认参数（待评审冻结）：

| 参数 | 默认建议 | 约束 |
|---|---|---|
| 周期 | 60 秒 | 可配 30–3600 秒 |
| 单轮业务超时 | 30 秒 | 可配 5–120 秒，且小于周期 |
| 连续业务失败次数 | 3 次 | 可配 1–10 次 |
| 连续成功恢复次数 | 2 次 | 可配 1–10 次 |
| 结果新鲜度 | 2 个周期 + 单轮超时 | 以中心接收时间和执行时间联合判断 |
| 两端清理宽限 | 10 秒 | 超时单独显示清理异常，不无限占用任务 |

资源不足时拒绝或跳过本轮并标记监控侧原因，不排成长队。首期并发上限在 SDK 实测后设置，配置中必须有明确上限。

### FR-06 公共能力：单轮结果与业务状态

单轮结果与聚合状态分别表达：

| 单轮结果 | 含义 |
|---|---|
| SUCCESS | 完成指定模板的业务收发证据校验 |
| FAILED | 任务确已执行，业务阶段失败或超时 |
| ERROR | 探针/SDK 初始化、调度或本地资源错误，无法完成有效业务验证 |
| CANCELLED | 人工停用或配置变更导致取消 |

业务状态使用正常、异常、未知；运行状态另设启用/停用，避免把停用等同正常。

- 首轮成功建立正常基线；首轮失败显示未知并注明“失败确认中”。
- 达到连续失败阈值后转为异常；阈值前保留原状态，同时展示最新失败和计数。
- 异常后达到连续成功阈值再恢复正常；不足阈值显示“恢复确认中”。
- ERROR、探针失联、未调度和结果过期转未知，不计入业务连续失败；连续计数中断。
- 从未知恢复需有新的有效执行结果，不允许凭探针心跳直接恢复业务正常。
- RTC 模板属于 BLACKBOX 层证据，不能覆盖 V1.0 容器状态，也不改变重启批准条件。

路径聚合：必选路径全正常才显示“已配置路径正常”；任一路径异常显示“存在异常路径”；无异常但有未知显示“部分路径未知”；未配置显示“未配置业务探测”。不使用空集合得出正常结论。

### FR-08 公共能力：通知

- 复用现有 HTTPS Webhook 的目标、HMAC 签名和持久重试机制，新增独立业务探测事件类型。
- 达到阈值的异常、恢复、以及持续未知的状态转换产生通知；持续相同状态不重复生成事件。
- 首次正常只建立基线；首次确认异常可通知。停用/删除/配置变更不伪装成业务恢复。
- 事件携带 event_id、产品线、任务/执行 ID、产品、集群、路径、前后状态、原因和发生时间，不伪造 node_id。
- 重试保持同一个事件 ID，接收端可去重。旧节点事件字段含义保持兼容。
- 通知发送失败仅影响投递状态，不改变探测结果或触发业务重启。

### FR-09 公共能力：历史与容量

- PostgreSQL 按产品线保存任务配置、最近状态、执行摘要和有界阶段证据，不存原始媒体或完整消息载荷；RTC 与 RTM 的执行记录不能混用。
- 执行明细建议保留 7 天，配置/停用和关键状态变化审计建议保留 30 天；均为本期新增探测数据的待评审默认值。
- 清理分批执行，不删除现有重启账本、幂等数据和 V1.0 审计。
- 为探测数据设置可配置容量预算；达到预算时明确拒绝/降级并将状态转未知，不静默丢弃结果后继续显示正常。
- 新增表占用纳入现有存储容量面板，并提供数据量估算：任务数 × 每日轮次数 × 保留天数 × 每轮平均大小。

### 4.1 权限与安全

| 操作 | Agora 人员 | 客户运维 | 探针身份 |
|---|---|---|---|
| 查看业务状态、详情、历史 | 允许 | 允许 | 仅自身任务协议 |
| 管理目标、任务、凭证、探针 | 允许 | 不允许 | 不允许 |
| 手动执行测试 | 允许 | 本期默认不允许 | 执行中心授权任务 |
| 重启业务容器 | 沿用 V1.0 控制 | 沿用 V1.0 控制 | 不允许 |

新增通信使用 TLS，独立探针身份只能领取自己的任务并上报本轮结果。中心检查执行 ID、配置版本和过期时间，拒绝重放与越权上报。凭证加密存储、最小范围分发；错误日志和截图不包含 Token、Secret 或真实用户内容。

## 5. 页面与操作

“业务探测”下提供“RTC 媒体探测”独立视图，展示本产品任务与路径，不与另一条产品线混合统计。

Agora 人员可登记探针、配置目标/凭证、创建任务、启停和手动测试；客户运维查看状态、详情和历史。任务详情包含配置版本、两端位置、SDK 版本、当前状态、最新结果、最近成功时间、阶段耗时、原因码和清理结果。

“服务状态”增加 RTC 业务摘要并跳转至本视图。未配置显示“未配置”，不能显示正常；业务状态与容器状态并列。失败与未知在操作区域给出原因和处理提示。

## 6. 异常与恢复

| 场景 | 行为 |
|---|---|
| 探针离线/本地资源耗尽 | ERROR 或结果过期，转未知；不伪造业务失败或恢复 |
| 目标拒绝认证 | 记录认证阶段失败和 SDK 原因 |
| 本地 Token 供应不可用 | 标记配置/凭证问题，不能自动重启 |
| 旧轮次/旧配置结果 | 去重并隔离，不覆盖当前状态 |
| 中心重启 | 恢复配置历史，等待新结果，不追赶积压轮次 |
| 数据库不可用 | 不可靠受理或保存失败必须可见，不持续显示旧正常 |
| 退出清理失败 | 与业务结果分开记录；限制槽位复用并提示 |

## 7. 验收与交付

| 编号 | 场景 | 通过条件 |
|---|---|---|
| RTC-AC-01 | 正常媒体收发 | 两端加入并有接收端帧证据；音频与视频按模板分别验收 |
| RTC-AC-02 | 加入成功但无媒体 | 接收超时失败，不能凭加入/发布回调标为成功 |
| RTC-AC-03 | 旧频道/旧轮次回调 | 不计入本轮，不覆盖最新结果 |
| RTC-AC-04 | 单媒体类型失败 | 音频成功不能抵消视频失败；任务按各自模板判定 |
| RTC-AC-05 | 探针断联和失败/恢复防抖 | 未知、异常、正常的转换和确认计数符合规则 |
| RTC-AC-06 | 并发与配置变更 | 同任务不重入；旧版本结果不覆盖新版本 |
| RTC-AC-07 | 权限与通知 | 角色限制、独立探针身份、HMAC、事件去重和重试有效 |
| RTC-AC-08 | 历史与离线交付 | 保留/清理不误删 V1.0 账本；可离线安装与回退 |

初始验收规模建议为 10 个本产品任务、2–4 个探针端。默认配置下故障确认目标为 3 个周期加单轮超时；资源、并发和检测时延须实测。Linux x86_64 优先，ARM 通过 SDK 验证后单独承诺。交付探针程序/镜像、SDK 依赖清单、配置指南、协议增量、验收记录和升级回退说明。
