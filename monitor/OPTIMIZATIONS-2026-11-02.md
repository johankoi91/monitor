## 账号与重启 Token

角色显示为管理者、使用者，内部角色 ID 和权限不变。管理者仍管理台账、操作审计、密钥和账号；使用者可查看状态、配置通知、执行受控重启及查看自己的结果。

同账号新登录成功后，旧会话立即撤销，旧页面下次请求收到 `401 SESSION_REPLACED` 并返回登录页。Token 是独立机器凭证，不占用页面登录会话；其所属账号停用或失去权限后，请求会被拒绝。

在接入密钥页签发重启 Token，自动归属当前账号。有效期默认 24 小时，可设置 1～720 小时；完整 Token 只返回一次并支持复制，服务端只保存随机凭证的哈希和到期元数据。列表按签发日期倒序显示，支持撤销、轮换。旧密钥对不再用于 REST 重启，部署后需重新签发并更新调用方。

机器调用仅需一个 Token，不需要 Base64 或额外 Key ID：

```sh
curl --request POST 'https://你的中心域名:19443/api/v1/operations/restart' \
  --header "Authorization: Bearer $RESTART_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"node_id":"111.230.192.59-avops-v1-canary","reason":"演练恢复","request_key":"唯一请求标识"}'
```

同一次操作超时重试时保留 `request_key`，新操作使用新值。`202` 仅表示受理；通过 `GET /api/v1/operations/{operation_id}`，携带相同 Bearer Token 查询结果。网页同时保留账号会话，并以 `X-AVOPS-Restart-Token` 传入本人重启 Token。节点白名单、Agent 本地规则、配置与实际容器 ID 校验、互斥及冷却机制继续生效。Agent WSS 的独立 Basic 凭证保持原用途。

## 通知分类与专属投递

`event_type` 区分 `STATUS_CHANGED`（变化）、`STATUS_SNAPSHOT`（首次正常状态同步）和 `WEBHOOK_TEST`（通道测试），状态通知用 `event_category` 分类：

| 分类 | 含义 |
| --- | --- |
| NORMAL | 启用正常订阅后同步一次当前正常节点；持续正常不重复发送，后续恢复时接收恢复通知 |
| CONTAINER_ABNORMAL | 容器缺失、退出、Readiness 失败等被监控对象异常 |
| COLLECTION_ABNORMAL | Agent 离线、采集数据过期；不能据此断言容器故障 |
| RECOVERED | 有效新数据证明当前状态恢复正常 |

通知页改为按接收地址管理配置，点击“添加配置”后选择已有地址或输入新的 HTTPS 地址，并勾选需要的事件类型。每条配置有独立签名密钥，支持编辑、启停、测试和删除，最多20条。一个地址可订阅多类事件，同一事件也可投递至多个地址；各地址的投递状态和重试独立持久化。已有地址、事件选择和密钥自动展示为现有配置，首次保存时平滑转换。更换地址需重新填写密钥，新增或重新启用配置时须通过接收端健康检查。

签名设置集中在编辑弹窗的一项：新配置可填写、生成和复制密钥；已有配置只显示“已配置”，点击“更换密钥”后才展开输入。TLS 证书域名放入可展开的可选设置。签名算法和 HTTPS 校验保持原规则。

“正常状态”按用户确认采用首次启用同步、后续按状态变化通知；同时勾选正常和恢复时不重复投递，中心重启也不重复初始化。已有配置不自动开启正常订阅。面向客户平台的接入评审、缺口和后续优先级见 [客户监控平台通知接入设计建议](客户监控平台通知接入_设计建议_2026-11-02.md)。

保持原有双签名、证书校验、10 秒响应预算、HTTP 200 + JSON 确认、重试和持久化去重机制。一次事件向各个订阅地址投递时使用相同事件 ID，内部以事件 ID 加配置 ID 分别保存各目标的投递结果；配置修改后旧队列按版本失效，避免向新目标补发旧目标的消息。当前仍只发节点通知，不发服务聚合通知。
