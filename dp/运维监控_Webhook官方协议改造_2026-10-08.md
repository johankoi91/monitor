# 通知 Webhook 改造与验证

依据：[声网接收 Webhook 文档](https://doc.shengwang.cn/doc/rtc/restful/webhook/receive_webhook)。发送器、接收服务、页面、OpenAPI、PRD、技术设计和原型同步更新，接入细节见 [WEBHOOK.md](../monitor/WEBHOOK.md)。

## 已实施

- 仅 HTTPS，完整验证证书链/域名，保持现有 IP URL + TLS ServerName 配置，不跟随重定向。
- 原始发送字节双 HMAC 签名：Agora-Signature SHA1、Agora-Signature-V2 SHA256；通知不发送 Basic Authorization。接收方先验签再解析，V2 提供但错误/为空不降级。
- 10 秒内 HTTP 200 且有效 JSON 才成功；确认体预算 4 KiB。失败首次立即重试，随后等待 1/5 秒，最多 3 次重试、4 次尝试；待发/结果仍持久化 PostgreSQL。
- 启用或更换目标/TLS/密钥前签名健康检查，失败保留原配置；检查不持有采集/查询互斥锁，并防止覆盖并发新配置。
- 页面可生成/复制新签名密钥、保存配置、测试已保存目标。密钥不通过配置查询接口返回。
- 保留本系统 STATUS_CHANGED 运维载荷；WEBHOOK_TEST 为明确的传输检查，不改变业务健康、不伪造 RTC 云频道事件。

## 部署与验证

中心 111.230.108.76、接收服务 114.132.190.201 已升级。切换前确认无执行中操作、无待发通知，暂停中心，备份后先升级接收端，再升级中心。备份在两机独立 /var/backups/avops-webhook-20261008，目录 0700，包含匹配的程序/配置与 PostgreSQL dump 或接收事件文件。不自动推送 GitHub，不停止/重启 RTC 业务容器。

旧配置的独立接收端 Secret 暂迁移为 HMAC 共享密钥，发送端 ID 移除，PostgreSQL 加密配置版本更新；接收端 AVOPS_WEBHOOK_SECRET 未设置时兼容旧 Secret。新增环境应配置独立签名密钥，将诊断 GET 的 Basic 凭证分开。中心来源 IP 白名单仍按用户要求关闭，接收端来源限制保留。

验证通过：

- 中心和接收端 Go race 测试、vet；React TypeScript/Vite 构建；OpenAPI YAML 解析。
- 官方 SHA1/SHA256 签名向量；原始体篡改拒绝；V2 无效/空值不降级；200 JSON/202/204/非 JSON 判断；最多 4 次尝试及首次立即重试；健康检查期间并发配置冲突保护。
- 真实 PostgreSQL 独立 avops_test 迁移/账号权限/恢复集成测试通过，未对生产库运行测试清理。
- 正式中心签名 WEBHOOK_TEST 收到 HTTP 200，healthy=true；接收端事件持久化，重复签名投递返回 duplicate=true，Basic-only POST 返回 401。
- 生产账号登录及通知页面浏览器检查通过，测试按钮显示签名健康检查成功，page_errors=[]。
- 既有台账 9 节点、4 Key、2 操作、2 固定角色及台账版本保留；账号登录/退出撤销和通知存储检查通过。

通知接收成功不等于业务恢复，重复和乱序仍须由接收方处理，轮询接口提供最新事实。本次验收未制造真实 RTC 业务故障。
