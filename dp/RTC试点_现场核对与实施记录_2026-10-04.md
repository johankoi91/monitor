## 1. 接入与授权

用户提供 SSH 端口 20220、APaaS 试点密钥、通知接收机及 TLS 证书，并指定 111.230.192.59 为开放重启/演练节点。三台机器以 root、id_ed25519_apaas_test 密钥接入成功。

节点授权没有取消既有“核心单点默认禁重启”的规则。本次 RTC 操作仅为 Docker/端口读取，没有停止或重启任何 RTC 业务容器，也没有执行业务故障演练。

## 3. RTC 候选服务核对

以下为检查时事实，不代表应有基线或开放白名单已由研发最终确认。

| 服务 | 容器 | 镜像版本 | 结果/证据 |
|---|---|---|---|
| RTC AP | agora_local_ap | release-v3_1_2-20251021 | running、host 网络；TCP 443/8002/8003 等由 local_ap 监听 |
| Balancer | agora_local_balancer | release-v1_4_1-20250826 | running、host 网络；TCP 2700 由 local_balancer 监听 |
| Native Edge UDP | agora_udp_media_edge_1 | release-v4_0_9-20251112 | running、host 网络；UDP 4001，另有本机 TCP 14001，不以辅助 TCP 证明媒体业务 |
| Web Edge | agora_web_media_edge_1 | release-v4_0_8-20251112 | running、host 网络；TCP/UDP 4501，另有本机 TCP 14501 |
| Native Edge AUT | 尚未发现对应容器 | 未确认 | 部署情况待核对，不能自动当成一个已确认应有但 MISSING 的节点 |

这些业务容器的 State 中没有 Docker Healthcheck 数据；旧 Docker 的模板对不存在字段会报错，已用兼容的运行态读取确认。

此外发现 VoSync、CapSync、Event Collector、Infra Helper，以及现有 InfluxDB/Grafana/Netdata。它们是否扩展纳管需要按原首期目录决定，不因为发现就自动加入。

现场端口信息来自 ss，不是应用功能检查；所选 TCP 探测目标和具体可重启节点还需要技术方案/研发核对。所有核心单点保持默认禁止。

## 4. 证书核对

edge.rtcdevelopers.com.pem 与对应私钥的公钥摘要一致，证书有效期为 2026-01-14 至 2027-01-13，SAN 包含 edge.rtcdevelopers.com、*.edge.rtcdevelopers.com。证书有完整 PEM 链，不覆盖三台机器的 IP。

私钥仅用于受保护部署，未写进代码或在输出中展示。公网访问使用证书域名与显式 IP 路由验证，没有关闭证书校验或变更 DNS。

## 5. 通知接收服务开发与部署

实现见 [notification_receiver](../notification_receiver/README.md)：HTTPS 18443、Basic Auth、中心来源限制、JSON 校验、可靠 JSONL 落盘、去重、容量保护和重启恢复。

已在 114.132.190.201 新增 avops-notification-receiver.service，以 avops-notify 用户运行；自恢复、资源限制与数据目录已设置。测试只重启该新接收服务，没有重启 RTC 或 RTM。

| 检查 | 结果 |
|---|---|
| 单元测试及竞争检查 | go test -race 通过 |
| 静态检查、Linux 构建、安装脚本语法 | 通过 |
| 中心到接收机的 HTTPS/证书/Basic Auth | 200，未使用跳过验证 |
| 中心来源缺少认证 | 401 |
| 首次连通性测试通知 | 200，persisted=true、duplicate=false |
| 同一事件再次投递 | 200，duplicate=true，记录只有 1 条 |
| 接收服务重启后再次投递 | 仍 duplicate=true，持久记录计数为 1 |
| 密钥及数据权限 | 环境文件 root 0600，私钥 root:avops-notify 0640，事件文件 avops-notify 0600 |

正式接收地址可配置为 HTTPS 接收 IP:18443/api/v1/notifications，并将 TLS ServerName 指定为 edge.rtcdevelopers.com；或为证书域名落实 DNS。测试使用 curl --resolve 保持证书主机名正确，接收者身份始终校验。
