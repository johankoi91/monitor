# RTC 试点资源指标与生命周期扩展

日期：2026-10-06；本次在现有 cAdvisor→Agent→中心链路增加资源分项、文件系统及生命周期。RTC 主机为 111.230.192.59，中心/UI 为 111.230.108.76。本次只更新独立 cAdvisor 配置及 Agent/中心程序，业务容器 StartedAt 保持 22:13 的 Docker 升级恢复时间。

## 已增加的内容

| 类别 | 页面/API 内容 |
|---|---|
| CPU | 使用核数、用户态/内核态、声明配额、受限调度周期比例、节流时间增长 |
| 内存 | 工作集及显式限额占比、使用量、RSS、缓存、Swap、峰值、分配失败累计 |
| OOM | cAdvisor 启动以来事件计数，Docker 当前 State 的 OOMKilled |
| 磁盘 | 每个块设备的读写吞吐、读写 IOPS、设备标识及采样可用性 |
| 网络 | 收发字节/包、丢包、错误速率；host 共享命名空间不归属单容器 |
| 文件系统 | 容器文件系统占用；宿主机 Docker 数据盘容量、空闲/可用空间、使用率、inode 总数/剩余/使用率 |
| 生命周期 | 创建、本次启动、最近结束、最后观测时间，运行时长、自动重启次数、退出码、Healthcheck、新鲜度 |

服务节点及发现表提供折叠的“资源与生命周期详情”。概要仍保留 CPU、内存和容器文件系统；详情按分组显示，避免默认展开大量字段。刷新 [运维监控](http://127.0.0.1:18086) 后可查看。

## 读取与口径

1. Docker Unix API inspect 取得声明限额和生命周期。NanoCpus 或 CpuQuota/CpuPeriod 计算 CPU 核数配额；Memory>0 才算显式内存限额。已确认无限制与未知分开，未限额不伪造百分比。
2. cAdvisor v2 stats 最新两样本计算 CPU 节流、用户态/内核态、I/O 和网络速率。计数器回退、跨启动、时间窗口无效和设备/接口变化不换算为假零。
3. 同时读取回环 /metrics，只提取 container_oom_events_total 的完整 ID 与数值，不转发原始标签。两个 HTTP 请求并行，共用 3 秒总超时；OOM 读取失败不破坏基础采集。
4. Agent statfs 读取实际 Docker 数据目录，默认 /var/lib/docker，可用 AVOPS_DOCKER_DATA_ROOT 配置。容量和 inode 属于宿主机共享文件系统，同机容器不能累加；不承诺监控所有挂载卷。

cAdvisor 现已启用 diskIO、oom_event。CPU 节流率是受限周期增量 / 总周期增量，不是整机 CPU 百分比；内存占比采用 working_set / 显式 Memory 限额。内存分配失败计数不等于 OOM。

现场的 `/dev/dm-0` 和 `/dev/vdb` 可以记录同一笔 I/O，按设备分别展示，不把两者相加；多设备情况下顶层磁盘汇总值为 null，真实读数在 disk_devices。没有设备计数时返回 NO_VALID_SAMPLES，等待采样，不伪造 0。

OOM 总数在采集器重启后重新开始，当前 Docker OOMKilled 也不是完整历史。Docker 自动重启次数不包括所有人工重启。Docker 保留的 FinishedAt 可能早于本次 StartedAt，页面标为“上一轮结束时间”；运行中的 exit_code 为 null，不把 0 当作上一次退出结果。

## 现场验证

23:36 左右复核，12 个 Docker 容器均取得已知限额状态、OOM 计数、Docker 数据盘和生命周期；8 个 RTC 基线节点及演练节点健康。

- 核心 RTC 容器未设置 CPU/内存限额：限额及占比为 null，limits_known=true，页面显示未设置。
- 演练容器声明 CPU 0.1 核、内存 32 MiB；工作集占比实测约 3.5%，随采样变化。没有有效调度周期时节流率为 null。
- 数据盘容量实测 249,682,382,848 字节，可用约 98.46 GB，使用率约 60.6%；inode 总数 121,974,784、剩余约 121,597,992。数值为瞬时记录，不是固定阈值。
- 8 个容器有可用 I/O 设备采样，分别展示 dm-0/vdb；4 个暂未取得有效计数，不显示假零。容器数量和状态随真实环境变化。
- Grafana 等 bridge 容器有可归属包速率，丢包/错误实测为 0；RTC host 网络对应读数留空并说明共享口径。
- OOM 计数本次均为 0，Docker OOMKilled=false；非零计数、137 退出码和 OOMKilled=true 用独立测试样例校验，没有制造业务内存耗尽。
- 创建时间为原部署时间，本次 StartedAt 为 Docker 升级恢复时间，最近 FinishedAt 属于上一轮；自动重启计数及 Healthcheck 按 Docker 事实展示。

Go race 测试、vet、React TypeScript/Vite 构建及 OpenAPI YAML 解析通过。测试覆盖资源配额、CPU 节流与分项、网络丢包/错误、I/O 计数重置和多设备不重复汇总、OOM 数字过滤、真实/缺失 statfs、生命周期缺失/零时间、退出码/配额换算。模拟浏览器验证了展开详情、每设备 I/O、容量/inode、生命周期和未知读数；真实接口验证现场数据。

## 边界

这些指标辅助资源排障，不替代 RTC 通话、媒体丢包/抖动/延迟等业务指标，不触发自动重启。不增加历史时序存储或事件中心；当前 OOM 累计与内存峰值来自采集器/内核当前计数，不是系统保存的完整历史。重启白名单、Key 和台账成员未因新增指标而改变。
