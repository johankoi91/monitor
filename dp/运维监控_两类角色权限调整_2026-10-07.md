# 两类角色权限调整

日期：2026-10-07。根据用户要求，账号角色收敛为 Agora 人员与客户运维，取消管理员/运维/只读和自定义角色。

| 模块或能力 | Agora 人员 | 客户运维 |
|---|---|---|
| 服务/节点状态、Agent 状态、资源与生命周期 | 可用 | 可用 |
| HTTP/HTTPS 通知配置与投递结果 | 可用 | 可用 |
| 自己的密码、登录与退出 | 可用 | 可用 |
| 容器发现、启动配置、基准台账读写/导出/历史 | 可用 | 不可访问 |
| 操作与审计、受控重启、未知结果核实、系统审计 | 可用 | 不可访问 |
| 接入密钥申请、签发、查看与停用 | 可用 | 不可访问 |
| 账号开通/停用、分配固定角色 | 可用 | 不可访问 |

Agora 人员保留通用功能，负责确认人员身份和账号授权，客户不能自行取得 Agora 权限。每个账号只能单选一个角色。注册默认 PENDING / customer_ops，开通前不能登录。Agora 角色不能代替独立重启 Key 或双端白名单。

## 实现与迁移

- 新角色 ID 为 agora / customer_ops。新增 inventory.read、baseline.read，将发现/启动配置及台账读取与通用监控分开。后端检查每个接口，客户直接访问专属模块返回 403；通知写入由 notifications.write 授权。
- React 客户页面只显示服务状态与通知投递、个人改密/退出；不再请求容器发现和台账接口。Agora 人员可看到完整模块和账号授权单选框。角色目录只展示两类固定角色。
- Key 申请移到 Agora 登录后的接入密钥页；未登录和客户申请拒绝。未绑定账号的旧 Key 不自动取得 Agora 身份，不能直接调用专属接口；机器访问须绑定有权限的 Agora 账号。Agora 账号会话仍可配合既有独立重启 Key。
- 事务迁移旧 admin → agora，其余旧角色 → customer_ops；保留账号 ID、密码和状态。旧角色、权限及账号分配快照写系统审计；撤销旧会话，documents 标记防止重复迁移。最后一个可用 Agora 账号受保护。

正式中心 111.230.108.76 已更新；当前只有 admin 一个账号，已迁移 Agora 人员。更新前确认无活动操作，并备份数据库及旧程序到 `/var/backups/avops-center-roles-20261007`，数据库文件为 before-roles.dump，已通过 pg_restore --list 校验。9 个节点、2 个操作、4 个 Key 和原台账版本均保留。
