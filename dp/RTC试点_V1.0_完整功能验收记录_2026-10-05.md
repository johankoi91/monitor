## 真实隔离验收

在 RTC 机器新增 avops-v1-canary（自建 scratch 镜像、127.0.0.1:18098、32 MiB/0.1 CPU），不使用任何既有 RTC/支撑容器作演练。验收 Agent 是独立 Docker 实例 avops-agent-acceptance，账本与正式 Agent 分开；中心是独立单元 avops-center-acceptance、29443/28084、独立数据目录及独立凭证。

验收规则只允许该 canary 的精确名、Agent、服务编码和镜像；没有开放 AP/Balancer/Edge。真实状态通知投递到原接收端，事件 cluster=rtc-v1-acceptance，明确标记隔离验收。

| 检查 | 实际结果 |
|---|---|
| 全链路发现、筛选来源、生成 YAML | 真 Docker 经 WSS 上报，API 选择生成基准并生效 |
| TCP 初始化/恢复 | 初始化约 22 秒取得两份成功证据；退出后清空旧恢复证据 |
| 第一次停止 canary 后发现异常 | 约 6.0 秒，30 秒目标内 |
| 原容器重启并复查 | 第一次约 10 秒；增加退出后恢复证据校验后第二轮约 20 秒 |
| 原样重启 | 容器 ID、镜像、脱敏配置快照一致，Docker 实际 StartedAt 更新 |
| 操作审计 | 第一轮 4 条、第二轮 5 条阶段记录，含来源/声明人/目标/证据/结果 |
| 中心重启后的同键重试 | 返回同一个 operation_id；Agent 账本第一轮只有一次 EXECUTING 和一次 EXECUTED |
| 兼容上一份二进制回退 | 隔离中心切换上一份二进制读取既有 WAL，同一第二轮请求仍复用既有操作；正式中心未回退 |
| 接收端实际事件 | 验收中心确认至少 6 条送达，无失败；接收端 recent 中存在该验收集群 |
| 正式状态 API | 8 节点台账，100 请求/10 并发，P95 约 77.6 ms，无请求失败 |
| 正式通知发送器 | 已启用并实际送达，检查时 pending=0/failed=0 |

第一轮在中心重启后立即检查同键遇到尚未监听的短暂窗口，服务就绪后重试通过；验收工具已用同一请求键做有界重试。没有把网络受理不确定改成新请求键。

所有 Docker 操作只针对新建 canary/验收 Agent/镜像 smoke 容器；既有 RTC 容器没有被停止、删除或重启。验收环境结束后清理其独立进程/容器，保留审计/证据；正式 8 节点台账不受清理影响。

## 自动与浏览器验证

Go test -race、go vet、Linux amd64 静态构建和 React 类型检查/生产构建通过。覆盖：重复帧只发一次 Docker 请求、执行中进程恢复未知而不重放、Docker 超时不重试、中心恢复先 QUERY、同键参数冲突、节点互斥/基准移出禁止、写入失败拒绝执行、人工核实不伪造健康、TCP/自动重启窗口、WSS 身份/旧会话隔离、通知固定 ID/载荷跨重启、TLS 错误、重定向不转发凭证、队列上限、配置变更不冒充恢复、损坏/截断尾部和单写者锁。

真实 WSS 协议测试使用 Docker Unix API 模拟器计数，证明重复任务及重复请求总共只有一个 POST；这与实际 canary 演练互为补充，不将模拟器当成业务故障验收。

内置浏览器的独立模拟环境验证 React 登录、55 容器列表、筛选、归类、YAML 保存和过滤后基准保留，以及操作/通知入口。正式页面资源也已部署；正式业务重启按钮保持规则禁用。

## 交付与实际限制

Linux x86_64/Kylin V10/Docker 18.09 试点；离线静态二进制、内嵌 React、Docker scratch 镜像、配置模板、安装/备份/升级/回滚说明、源代码/锁文件和 OpenAPI。镜像不含真实 env、证书私钥或运行数据；没有强制公网 pull。

离线包：monitor/build/release/monitor-1.0.0-linux-amd64.tar.gz（约 28 MiB）。程序/镜像 SHA256SUMS 全部通过，归档源代码包含 React 与真实中心/Agent 模块，未包含 PEM、私有 env、curl 凭证、JSONL 或原始视频。Docker 中心镜像以 UID/GID 65532 运行，独立镜像 smoke 实例通过启动检查；实际验收 Agent 使用离线 Agent 镜像，正式部署仍采用 systemd。

试点中心约 10–15 MiB 内存，Agent 有 128 MiB/25% CPU 上限；这是当前规模观测，不承诺未经验证的客户规模。数据配额/日志轮转与保留见 OPERATIONS，WAL 满或损坏不靠删除幂等记录恢复。

RTC 核心节点的实际重启批准仍须研发确认后逐个配置；产品功能已开发，但没有代替研发批准或用真实业务做高影响故障演练。ARM、RTM/Blackbox、主备、历史时序、告警处置回传和角色体系仍按规划后置。公共域名 DNS 的常规访问需现场落实，当前本机 viewer 保持 TLS 服务器身份校验。
