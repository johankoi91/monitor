## 1. 产品定位

系统面向私有化 RTC/RTM 节点的运维人员，提供真实 Docker 容器发现、服务基准管理、节点健康状态、资源观测、受控重启、操作审计、通知配置和账号权限管理。

系统将“容器和采集通道状态”与“音视频业务成功”分开表达。容器运行正常只能说明容器层状态正常，不能自动证明 RTC/RTM 业务链路正常。

## 2. 用户与权限

系统只有两类内置角色：

| 角色 | 主要能力 |
|---|---|
| Agora 人员 | 查看服务、容器发现、维护基准、资源详情、通知、全局操作与审计、签发/停用重启 Key、账号开通和角色分配 |
| 客户运维 | 查看服务和资源、查看通知结果、使用绑定本人的重启 Key 发起受控重启、查看本人重启结果、修改密码 |

账号注册后为 `PENDING`，由 Agora 人员开通并分配固定角色。角色不能自定义。后端每个接口都校验权限，前端隐藏按钮不构成安全边界。

账号登录使用 Bearer 会话。浏览器保存可撤销的会话令牌以支持刷新后恢复登录，不保存账号密码；退出登录、改密、账号停用、角色变化或会话失效时清理令牌。会话有效期和撤销由 PostgreSQL 管理。

重启还需要独立的 `RESTART` Key。账号角色、普通机器凭证或页面上的重启开关都不能单独替代该 Key。

## 3. 页面与功能

### 3.1 服务状态

“服务状态”按集群和服务展示已纳管节点。页面提供集群标识下拉筛选，默认显示全部集群。

每个容器卡片采用以下结构：

```text
容器名                                      容器状态 | 重启 | 查看详情
IP · 时间
资源摘要
```

状态、重启、查看详情三个控件位于同一操作容器，并整体贴齐内容区最右侧。点击“查看详情”后展开资源详情、文件系统、生命周期和启动参数页签；默认不展开详情标题。

节点状态包括 `HEALTHY`、`UNHEALTHY`、`UNKNOWN`。服务聚合状态包括 `HEALTHY`、`DEGRADED`、`UNHEALTHY`、`UNKNOWN`。状态同时返回检查层级、原因码、原因说明、采集时间和新鲜度。

重启按钮只有在当前基准开放重启、当前账号有权限时可点击。Agent 离线、容器缺失、规则未批准、操作存储不可用、冷却期或其他前置条件不满足时，按钮或确认框显示具体原因。

### 3.2 容器与基准台账

“容器发现”从已接入 Agent 的真实 Docker 快照中分页获取候选容器，支持按主机 IP、容器名称、镜像、运行态筛选。筛选只影响列表，不会自动移除既有基准成员。

纳管流程：

1. 勾选在线且快照有效的候选容器。
2. 填写合法集群编码，可填写多个 TCP 端口。
3. 点击“加入待保存变更”，生成服务归属和变更预览。
4. 在“变更预览”确认新增或移出内容。
5. 点击“保存并生效”，生成新基准版本并可下载 YAML。

错误使用红色 Alert；非法集群编码、端口错误、候选过期、版本冲突和保存失败都在对应操作区域提示。变更预览位于“选中容器的服务归属”下面。

新纳管节点默认关闭重启权限。已纳管节点可单独设置端口检查和重启权限。重启权限变更需要基准版本一致，执行中或结果未知的节点不能移出或改绑定。

### 3.3 操作与审计

“操作与审计”展示全局受控重启记录，包括状态、目标、请求时间、执行阶段、结果、来源和操作 ID；客户运维只能查看本人发起的结果。

同一节点的执行中或结果未知操作会加锁。请求使用幂等 `request_key`，网络超时后可用相同请求标识查询，不能因未收到响应而盲目再次重启。

该板块同时展示“存储容量”面板，包括数据库占用、容量提示阈值、数据盘可用空间、会话清理结果和各表占用。容量阈值是提示，不是硬配额。

### 3.4 通知投递

通知页面支持配置一个 HTTPS Webhook、启停开关、TLS Server Name 和独立签名密钥，并展示待发、已送达、失败、丢弃和最近事件。

通知使用独立凭证和 HMAC，不复用账号、Agent 或重启 Key。发送失败进入持久队列并按事件 ID 重试；通知失败不会触发业务重启。

### 3.5 接入密钥

Agora 人员在“接入密钥”页面签发和停用重启安全 Key。签发只填写名称，所属账号自动绑定当前账号；Secret 只显示一次并支持复制，页面不再次返回已隐藏 Secret。

### 3.6 账号与权限

Agora 人员可查看待开通、已开通和停用账号，开通账号并分配 Agora 人员或客户运维角色。账号可修改自己的密码；改密后旧会话失效。

### 3.7 资源与启动参数

资源摘要包含 CPU、内存工作集、容器文件系统和运行时间。详情页提供资源、文件系统、生命周期和启动参数信息。

启动参数来自 Agent 对真实 Docker 容器的现场读取，展示镜像、命令、环境、挂载、端口、网络和重启策略；敏感字段按实现规则脱敏或标记不完整。启动参数不是历史配置，也不提供任意命令执行。

## 4. 状态口径

| 层级 | 判断内容 |
|---|---|
| `AGENT` | Agent 是否在线、报告是否新鲜 |
| `CONTAINER` | 容器是否存在、运行、退出或反复重启 |
| `READINESS` | TCP 检查或 Docker Healthcheck |
| `BLACKBOX` | 真实 RTC/RTM 业务流程；当前版本未实现 |

健康状态按应有节点聚合，不用已发现数量替代应有数量。Agent 离线或数据过期时保留基准成员并标记未知；容器缺失不会被静默移除。

资源数据缺失、过期或共享归属时显示不可用/未知，不用 0 伪造数据。主机数据盘和 host 网络属于共享资源，不能错误归属于单个容器。

## 5. 受控重启需求

一次重启必须同时满足：

- 当前账号具备重启权限；
- 使用有效的独立 `RESTART` Key；
- 当前基准节点已开放重启；
- 中心规则和 Agent 本地规则均批准目标；
- Agent 在线且容器快照新鲜；
- 容器 ID、名称、镜像、启动指纹一致；
- 没有执行中/未知操作，且不在冷却期；
- 操作记录可靠落盘。

系统只执行精确目标的 Docker 原容器重启，不执行任意命令、不重建容器、不自动重启业务节点。重启成功还需要复查检查层级；执行结果未知时保持锁定，要求现场核实后关闭。

## 6. 安全与数据

- 公网入口使用 HTTPS；证书身份为 `edge.rtcdevelopers.com`，直接使用 IP 可能出现证书域名不匹配。
- 当前试点 `AVOPS_ALLOWED_IPS` 按现场要求为空，账号、角色、TLS、Agent 身份和同源写入保护仍生效。
- PostgreSQL 保存账号、角色、会话、台账、操作、审计、Key、通知和最新快照。
- 数据库密码、存储密钥、TLS 私钥和 Agent 密钥不进入仓库或普通页面响应。
- 页面写请求要求同源和 `X-AVOPS-Request: 1`，中心设置安全响应头。

## 7. 已实现与未纳入

### 已实现

真实 Agent/WSS 上报、Docker 容器发现、基准 YAML、集群筛选、服务状态、资源指标、启动配置查看、账号/RBAC、PostgreSQL、重启 Key、受控重启、幂等和恢复、操作审计、HTTPS Webhook、存储容量面板和离线静态前端。

### 当前未实现

真实 RTC/RTM 黑盒业务探测、告警规则中心、Alertmanager、自动业务恢复、主备高可用、多中心、完整租户隔离、自动基准历史回滚和完整独立系统审计页面。

## 8. 验收标准

1. 登录、刷新恢复、退出和改密会话行为正确。
2. Agora 人员可发现容器、生成预览、保存基准并下载 YAML。
3. 筛选和分页不会误移除未显示的基准成员。
4. 服务状态正确显示集群筛选、容器状态、资源和新鲜度。
5. 重启按钮按基准、权限和实时前置条件工作，并显示明确阻断原因。
6. 重启请求具备幂等、互斥、未知结果锁定和操作审计。
7. 客户运维只能使用本人绑定 Key 查看和执行允许范围内的重启。
8. 通知、存储容量、账号权限和前端错误提示可用。
